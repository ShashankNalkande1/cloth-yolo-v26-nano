About this model YOLO26n · edge test build

A tiny fabric‑defect model built purely to test the inspection pipeline on Arduino / Raspberry Pi class hardware — not a production‑grade detector. Detects 4 defect classes: hole, oil, slub, snag.

Formats: ~5 MB .pt (PyTorch — retrain/export) · ~9 MB .onnx (portable — runs anywhere, no PyTorch).

Intentionally tiny → cheap to host on free tier (Render / Railway / HF Spaces), no GPU needed. Next step: train a bigger, more accurate model for real‑world close‑up defect detection.

Why this model? — the honest story

// a feasibility build for edge hardware

Okay, let me be straight with you. I didn't train a big, fancy model here — and that was on purpose.

My whole goal with this fabric inspection build was to answer one simple question: "Does this pipeline even work on Arduino / Raspberry Pi close‑shot images?" Camera → defect detection → alert. If that basic loop works on the cheapest possible setup, then I know the idea is real. Accuracy can come later.

So why YOLO26n (Nano) and not a bigger one?
A bigger variant — s, m, l, or x — means GPU training and GPU hosting. For a feasibility test on edge devices, that's just burning money to answer a question a small model can already answer. Nano gave me the same signal at a fraction of the cost.

The YOLO26 family launched on 14 January 2026 — and Ultralytics dropped all size variants on the same day. Nano is the smallest (~2.4M params), the fastest, and was built specifically for CPU, mobile, and edge chips like the ESP32‑S3 or Raspberry Pi. That's exactly the audience I wanted to prove this for.

The model itself is tiny — ~5 MB .pt and ~9 MB .onnx. That means it runs comfortably on a free Render / Railway / Hugging Face Spaces instance with zero GPU. No credit card, no cloud bill, no cold‑start drama.

Right now it detects four fabric defects: hole, oil, slub, snag. Not perfect, not production‑ready — but it proves the full loop works end‑to‑end on close‑shot images from low‑cost hardware.

The impact: The fabric inspection pipeline is live on free infrastructure today. Next step is to train a heavier, more accurate model and push it onto Arduino / ESP32‑S3 edge hardware for true on‑device defect detection. Same code, same flow — just a stronger brain in the middle.

That's really it. This isn't a flex — it's a proof. The small model was the whole point: show it works, cheaply, before investing in the big one.
